🧪 Training & Testing Validation Protocol

Choose how training and evaluation datasets are provided and configure your retraining protocol.

Each resample repeats the process (missing-value filling, encoding, scaling, training and, if switched on, the automatic tuning) on patients drawn with replacement. The model is scored on its resample and on the original patients; the average difference (the optimism) is subtracted from the performance of the final model trained on all patients. Flexible models (Random Forest, boosted trees, k-NN, neural networks) are reported with the .632+ estimate instead, which scores each resampled model on the patients it did not see. When several models are compared by cross-validation, the choice of the best model is repeated in every resample too. Neural networks and the Ensemble use at most 50 resamples, and their tuning is not repeated (too slow). There is no separate test set, so the results table shows corrected estimates; for external validity, test on an independent cohort (Option B).

⏱️ With automatic tuning switched on, every resample re-tunes the model, so a run can take several minutes per model (shown with a time estimate). Start with 50 resamples to see how long it takes.

The app tries several combinations of each model's main settings (e.g. k for k-NN, tree depth for Random Forest, the ridge penalty for Logistic Regression, dropout and weight decay for the Neural Network) and keeps the one that scores best on the ranking metric. Each combination is judged by cross-validation inside the Training set: the Training set is split into 5 (or 3) parts and each part takes a turn as a mini-test while the model learns from the rest. The Testing set is never used for tuning, so its final score stays a fair check. Your current settings are always one of the candidates, so they are only changed if another combination does better; the chosen settings are then shown in each model's settings panel. Missing-value filling, encoding and scaling are redone inside each part, so the mini-tests never influence the preparation. 🔬 Strictly Ordered 7-Step Clinical ML Pipeline

Clinical ML protocol with training-only preprocessing: stratified train/test split (default 80/20; rows with a missing outcome excluded), imputation fitted on the training split only, skewness screen & correlation review (Pearson vs Spearman), VIF multicollinearity review, univariate baselines, SMOTENC balancing of the training split, Random Forest feature scout, and algorithm-constrained final evaluation.

Step 2: Continuous Variable Correlation Check (Pearson vs. Spearman)
Continuous and ordinal variables in the Training set are screened for skewness (bias-adjusted Fisher–Pearson coefficient, G₁ = √(n(n−1))/(n−2)·g₁, as in SciPy skew(bias=False)) using the rule of thumb |G₁| ≤ 1 (approximately symmetric). This is not a formal normality test. Pearson (r) is calculated when both variables pass the screen; Spearman (ρ) is calculated if one or both are skewed. High-collinearity pairs (|r| or |ρ| ≥ 0.8) are presented below to allow dropping one or keeping both.

Step 3: Variance Inflation Factor (VIF) Check
Categorical variables are one-hot encoded (dropping reference category to eliminate dummy trap) and continuous variables standardized. VIF is computed for all surviving features; multi-level categorical features use the Generalised VIF (Fox & Monette), which captures the joint collinearity of all their dummy columns and is shown on the VIF scale as GVIF1/df. Features with VIF > 5 indicate severe multicollinearity and can be permanently eliminated from both Train and Test sets.

Features Multicollinearity Table (VIF & R²)

VIF > 5 indicates high multicollinearity ($R^2 > 0.80$). Check variables to drop and click 'Drop Selected Features'.

🧪
Step 4: Univariate Statistical Testing Check
Informational baseline testing of surviving original variables against the Target: One-Way ANOVA (or t-test) for continuous features and Pearson Chi-Square (χ²) for categorical features. Variables are sorted from lowest p-value to highest. Variables are NOT automatically dropped at this step.

Step 5: Imbalance Handling (SMOTENC)
Counts how many Training-set patients have each outcome. If the rarer outcome makes up less than 30% of the Training set (or, for outcomes with more than two groups, the smallest group is less than about 43% the size of the largest), SMOTENC creates synthetic (made-up but realistic) patients for that outcome, each blended from similar real patients, until the outcome groups are equal in size. Measurements such as age are blended to in-between values; categories such as sex take the most common value among the similar patients. The Testing set is never changed: it contains only real patients, so the results reflect real-world performance.
Evaluating Training set class balance...
🔒 The Testing set is never resampled: it keeps the true outcome prevalence. (Its missing predictor values were filled in Step 1 using Training-set values only.)
🌲
Step 6: Model-Driven Feature Ranking (Random Forest Scout)
Ranks the predictors by how useful they are. A quick "scout" Random Forest is trained on the balanced Training set from Step 5 (it is used only for this ranking, not as one of the final models). Each predictor is scored by how much it helps the trees separate the outcome groups (Mean Decrease in Impurity). The weakest 30% of predictors are then left out for k-Nearest Neighbours and Naive Bayes in Step 7, because weak predictors add noise that easily misleads these two models. The other models use all remaining predictors. The ranking uses the Training set only, and it is a practical filter rather than a definitive clinical ranking: it tends to favour continuous measurements over simple yes/no predictors.

Step 7: Algorithm-Specific Training & Constraints
Applies strict stability constraints to each algorithm:
  • k-NN & Naive Bayes: Use only the top 70% of features by Step 6 RF importance (fewer noisy inputs for distance- and likelihood-based models).
  • Random Forest: All surviving features (tree splits are scale-free and the forest selects features per split).
  • Gradient-Boosted Trees: All surviving features; shallow trees, shrinkage, row subsampling and early stopping on an internal validation split of the training rows.
  • Neural Network (MLP): L2 weight decay + dropout, with early stopping on an internal validation split of the training rows (the test set is never used in training).
  • Logistic / Ridge Regression: Applies L2 penalization to stabilize any remaining minor collinearity.
  • Voting Ensemble: Equal-weight soft vote of its base models; scaling and one-hot encoding fitted on the Training set only (as for every model).
All models are evaluated on the held-out Testing set (never resampled) and ranked by the selected primary metric (default: macro F1-Score; regression: R²). By default the ranking uses cross-validation inside the Training set, so the top model's test score is an honest estimate; if you choose to rank on the Testing set instead, the top score is optimistically biased. Either way, confirm the chosen model on an independent cohort.
