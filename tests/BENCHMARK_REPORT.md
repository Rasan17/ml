## Design

- Datasets (scikit-learn): breast cancer (binary, 569×30), wine (3-class, 178×13), diabetes (regression, 442×10). 5% of predictor values blanked at random (seeded) to exercise imputation.
- 10 seeded 80/20 train/test splits per dataset (stratified for classification), identical for app and Python.
- App side follows Option A: median imputation and z-scoring fitted on the training split, applied to the test split.
- Python side: `SimpleImputer(median)` + `StandardScaler` fitted on the training split; k-NN, RandomForest, LogisticRegression/Ridge (equivalent penalty), GaussianNB from scikit-learn; a PyTorch MLP mirroring the app (Glorot init, ReLU, dropout, Adam, L2 on hidden kernels, mini-batches, early stopping on a stratified 15% validation split of the training data with best-weight restoration); SMOTENC from imbalanced-learn.
- Hyper-parameters (shared): `knn_k`=5, `rf_trees`=100, `rf_depth`=8, `glm_lr`=0.05, `glm_epochs`=150, `glm_lambda`=0.01, `nn_hidden`=[64, 32], `nn_epochs`=100, `nn_lr`=0.005, `nn_batch`=16, `nn_dropout`=0.1, `nn_l2`=0.0001, `nn_val_fraction`=0.15, `ens_nn_hidden`=[48, 24], `ens_nn_epochs`=35, `ens_rf_trees`=30, `ens_rf_depth`=6, `gbm_rounds`=200, `gbm_lr`=0.1, `gbm_depth`=3, `gbm_l2`=1.0, `gbm_bins`=32, `gbm_min_leaf`=5.
- Metrics for both sides are computed by scikit-learn from the raw predictions.
- **Verdict rule for stochastic models** (fixed before running): paired difference app − Python over the splits; PASS if the 95% CI lies within ±margin (AUC 0.02, accuracy 0.03, macro-F1 0.03, R² 0.05); FAIL if the CI excludes 0 and |mean difference| exceeds the margin; otherwise INCONCLUSIVE (not shown to be equivalent at this sample size).

## Interpretation notes

- Random Forest and neural network results cannot match prediction-by-prediction: the libraries use different random-number streams, and the app's trees search ~10 candidate thresholds per feature rather than all of them. Agreement is therefore judged on performance across paired splits.
- The app's logistic/ridge model uses a fixed number of gradient-descent iterations (default 150), whereas scikit-learn solves to convergence; differences in that row reflect the iteration budget, not the formula (the formula itself is verified exactly in `tests/reference_check.py`).
- k-NN with distance weighting: the app uses 1/(d + 1e-5) rather than 1/d, so probabilities may differ in the 5th decimal; class predictions are expected to be identical.
- k-NN rows whose k-th and (k+1)-th neighbours are at exactly the same distance are excluded from the exact comparison: which tied case is "k-th" is implementation-defined (scikit-learn follows its tree traversal; the app uses a seeded tie key). Exact ties are common with the Chebyshev metric and with imputed values.
- Calibration: both the app and the Python references show the same pattern (logistic/ridge, Random Forest and the ensemble under-confident, slope > 1; the MLP over-confident, slope < 1), i.e. it is a property of the model types and settings, not of the implementation. Probabilities should not be read as calibrated risks.
