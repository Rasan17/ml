# Response to the ChatGPT review, October 2026

Each recommendation was checked against the code.
- **Already in place:** the existing implementation and its test are named.
- **Valid and missing:** it was fixed, and a test was added.

| # | Recommendation | Verdict | Where / what changed |
|---|---|---|---|
| 1 | Select models by cross-validation in the Training set; test-set selection only exploratory; separate selection score from test score | Already in place; warning strengthened | Cross-validated selection is the default. Test-set selection is labelled optimistic. The leaderboard shows the CV score next to the test score. **New:** if the leader was chosen on the Testing set, the results notes now carry a prominent "Exploratory model choice" warning. |
| 1b | No test-set information in feature selection, tuning, calibration fitting or threshold optimisation | Already in place | Tuning and selection run inside the Training set. Recalibration is fitted on out-of-fold Training predictions. Youden's threshold comes from out-of-fold Training predictions. Permutation importance on the Testing set is shown only, never used to tune. |
| 2 | Every preprocessing step refitted inside each fold; SMOTENC and feature selection on the training fold only; patient grouping; date-based validation; external validation uses only training-fitted parameters | Already in place | One shared fold engine (`buildFolds`) refits imputation, encoding, scaling, SMOTENC and, optionally, top-70% selection inside each fold. External validation applies the saved preprocessing unchanged. |
| 2b | Deliberately constructed leakage datasets that must fail visibly | **Added** | `audit_regressions.js`, "leakage canaries": noise data with repeated patients reaches AUC 1.00 under a random split but 0.50 under the patient-grouped split. Folds never split a patient. A date split predicts strictly later records. Option C on pure noise was already tested (`end_to_end.js`). |
| 3 | Calibration-in-the-large, slope, plot with uncertainty; raw vs recalibrated; recalibration fitted on training data only; Brier explained; baseline Brier | Partly in place; **completed** | Slope, intercept, plot, and before/after recalibration values already existed. **New:** observed vs mean predicted risk (O:E); 95% Wilson intervals on every calibration-plot group; reference Brier (everyone given the observed rate) and scaled Brier; a plain explanation that the Brier score mixes calibration and discrimination and depends on prevalence. |
| 4 | Small datasets: grouped folds, cluster bootstrap, counts of patients, events and non-events per metric, warnings when events are few, "not estimable" | Mostly in place; **completed** | Grouped folds and patient-level bootstrap already existed, and non-estimable metrics are already reported as such. **New:** a "Testing set" note gives the records in each outcome group. It warns when the smallest group has fewer than 50, says results are illustrative below 10, and says AUC cannot be estimated if a group is absent. Repeated cross-validation is not added: bootstrap internal validation (Option C, Harrell's and .632+) is the method TRIPOD recommends for small cohorts. |
| 5 | Ensemble: name it accurately; weights without test outcomes; compare with constituents | Already in place | It is called "Voting / Weighted Ensemble", not a Super Learner. | 6 | Plain-language interpretation panel; baseline comparison; consequences of errors; limitations; out-of-distribution warning | **Added** | New "🩺 In plain language" panel after training, covering: what is predicted and for whom (with a prompt to state the time horizon); what the probability means, given its calibration; AUC in words; comparison with giving everyone the average risk; false negatives and false positives per 100 patients at the chosen threshold; and the limits of the validation design. **New unusual-patient warning:** a patient whose *combination* of values is unlike the training patients (Mahalanobis distance beyond the 99th or 99.9th percentile of the training patients) is flagged in single and batch predictions, even when every value is in range. | 7 | Test-suite runtime; deterministic small datasets; separate slow suites; bundle rebuilt from source; CI in all browsers | Already in place | Suites run separately in CI (module, edge cases, audit regressions, end-to-end, reference, NN forward pass; browser tests in Chromium, Firefox and WebKit). | 8 | Reproducible network-request audit; disclosure of export contents; shared-computer warning; versioning; governance | **Completed** | **New browser test** records every network request during a full analysis (training, single and batch prediction, external validation): all must be downloads of the app's own files, and none may send data. | 10 | Retrained model vs evaluated model distinguished | Valid; **clarified** | After retraining on 100% of patients, the banner now says the results are those of the split-trained models, and that the retrained models have not themselves been tested and should be confirmed on new patients. |

## Second ChatGPT review (October 2026)

| Point | Verdict | What changed |
|---|---|---|
| Pipeline CV does not repeat outcome-based screening | Valid; **fixed** | Step 4's univariate screening (the only pipeline screening that uses the outcome; correlation and VIF do not) is repeated inside every cross-validation fold. Each predictor screened by significance is kept in a fold only if significant on that fold's training patients; the user's manual overrides are kept. The results report how often each predictor was selected across folds. Browser test. |
| Browser and end-to-end suite not completed in the reviewer's environment | Environment limitation | The full suite runs on every push in GitHub Actions: Chromium, Firefox and WebKit, plus the end-to-end, regression, reference and forward-pass checks (all passing; see the Actions tab). The suite needs Node's `@playwright/test` (`npm ci`, then `npx playwright install`, then `npm run test:ui`). The Python `playwright` package cannot run it. The "failed test" in the archived `test-results` folder came from a local run on 17 October in which the browser engine was not installed; it was not an app failure. The folder is now removed and is excluded from the repository. |
| Make the instability of small-sample estimates prominent | Valid; **improved** | The plain-language panel now shows the AUC's 95% interval and, when it is wider than 0.2, says that the true AUC could range from one quality label to another and that the model ranking is uncertain. This adds to the Testing-set note on small groups. |
| Unusual-patient warning is a screening aid | Valid; **clarified** | The single and batch warnings now say it is a screening aid, not proof that the prediction is wrong. |
| Verify why data are missing | Valid; **clarified** | Step 3 and the pipeline state MICE's missing-at-random assumption, and ask the user to consider why values are missing. |
| Model selection, calibration, software verification vs clinical validation | Already in place | Covered in the first response. The app presents itself as research and educational software, not validated for clinical decisions. |
